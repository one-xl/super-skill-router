# Skill Policy

本文档规定了技能的读取、使用、安装和更新的安全控制边界。

## 惰性加载控制 (Token 节约红线)

- **单路径锁定**：锁定分类后，只读取该分类的标签和子类索引。禁止在决策中交叉读取无关分类。
- **条件触发读取**：只有在 `SKILL_TAG.md` 中的读取条件完全命中时，才允许读取对应子目录下的 `INSTRUCTION.md`。禁止盲目通读。
- **主技能上限**：单次任务原则上只允许加载和阅读 **1 个** 主 `INSTRUCTION.md`。

## 行为与确认矩阵

| 行为类型 | 允许范围 | 需要用户明确确认 |
| :--- | :--- | :--- |
| **读取文件** | 读取索引、标签文件、满足条件的主 Skill | 通读整个技能库、读取未登记的隐藏目录 |
| **代码修改** | 无 | 新增、覆盖或修改任何 Skill 文件及配置 |
| **外部安装** | 搜索候选 Skill、生成安装建议 (Proposal) | 执行 `npx skills add`、拉取外部未知源 |
| **全局同步** | 运行自检审计（doctor 脚本） | 镜像同步覆盖至全局 `~/.codex/skills/` |

## 全局默认辅助 Skill 策略

1. **karpathy-guidelines**：
   - **触发**：写代码、修改、重构、审查、修 bug、加测试或方案设计。
   - **规则**：自动加载，只作为工程实现的规范约束，不作为业务逻辑知识库。
2. **codegraph**：
   - **触发**：代码库探索、查找定义/类/函数、变更影响分析。
   - **规则**：自动作为代码导航和依赖分析工具使用，代替大范围的文件读取。
3. **headroom**：
   - **触发**：大日志输出、编译异常堆栈、长历史。
   - **规则**：自动对冗余文本进行无损压缩。
